# Feature — 기능 개발

이 문서는 [SKILL.md](SKILL.md)의 한글 번역본입니다. 스킬 실행 지침의 기준은 영문 원문입니다.

**설명:** 부작용을 파악하고 의도한 변경 범위 밖의 동작을 유지하면서 기능을 추가, 수정, 제거하고 영향을 받는 작업 흐름을 검증합니다.

요청에 따라 기능을 추가, 수정, 제거하되, 기존 기능에 미치는 의도하지 않은 영향을 주의 깊게 살펴봅니다.

## 작업 방식

- 사용자가 다른 언어를 요청하지 않는 한 사용자의 언어로 답합니다.
- AGENTS.md나 CLAUDE.md를 포함한 프로젝트 지침을 따릅니다. Git 작업 방식, 도구, 코딩 규칙, 승인 요건은 해당 지침과 기존 사용자 선호에 맡기며, 이 스킬은 이를 덮어쓰지 않습니다.
- 짧은 요청에서 시작합니다. 질문하기 전에 프로젝트를 살펴보고 영향 영역을 추론하며 기존 패턴을 활용합니다. 해결되지 않은 선택이 동작, 호환성, 데이터, 운영 영향에 실질적인 차이를 만들 때만 질문하고 간결한 추천안을 제시합니다.

## 수정 전 영향 파악

- 요청이 기능 추가, 수정, 제거 중 무엇에 해당하는지 또는 여러 작업의 조합인지 판단합니다. 의도한 동작 변화와 유지해야 할 기존 동작을 정합니다.
- 추가 시에는 기존 작업 흐름과의 상호작용을 확인합니다. 수정 시에는 의도한 동작 변화와 회귀를 구분합니다. 제거 시에는 남아 있는 호출부, 진입점, 설정, 테스트, 외부 사용처를 추적하고, 요청한 변경으로 불필요해진 의존성만 제거합니다.
- 기능 제거와 저장 데이터의 영구 삭제 또는 파괴적인 마이그레이션을 구분합니다. 기능 제거 요청만으로 해당 작업의 권한까지 있다고 판단하지 않습니다. 필요한 경우 범위를 확인하고 적용되는 승인 요건을 따릅니다.
- 수정할 파일을 넘어 관련 호출부, 사용처, 공통 코드, 데이터 흐름을 추적합니다. 파일이 가까이 있다는 이유만으로 영향을 판단하지 않고 기존 테스트와 계약을 확인합니다.
- 코드에서 근거를 찾을 수 있는 구체적인 위험을 파악합니다. 예를 들어 공통 컴포넌트 동작, API 사용처, 저장 데이터, 권한, 캐시, 백그라운드 작업, 성능 등이 있습니다. 이번 변경과 관련된 위험만 조사합니다.
- 중요한 영향 영역과 확인 방법을 짧게 알립니다. 기능에 호환성을 깨뜨리는 변경이나 요청 범위 밖의 중요한 절충이 필요하다면, 그 결정에 의존하는 작업을 진행하기 전에 사용자와 해결합니다.

## 구현과 검증

- 요청한 결과를 충족하는 가장 작고 일관된 변경을 적용합니다. 의도한 변경 범위 밖의 계약과 동작을 유지하며, 관련 없는 리팩터링이나 의존성 변경을 피합니다.
- 의도한 동작과 파악된 위험에 노출된 기존 작업 흐름을 검증합니다. 기능 제거 시에는 제거한 진입점을 의도대로 사용할 수 없는지, 유지한 작업 흐름이 여전히 동작하는지 확인합니다. 회귀 검증을 없애는 대신, 더 이상 맞지 않는 테스트를 요청된 동작에 맞게 수정합니다. 가능한 경우 관련 회귀 테스트를 추가하거나 갱신하고, 중요한 실패 경로와 통합 경계를 포함합니다.
- 프로젝트의 관련 검증을 실행한 뒤 diff를 검토하여 의도하지 않은 변경과 놓친 호출부를 확인합니다. 공통 코드를 변경했다면 요청한 동작뿐 아니라 기존 사용처도 확인합니다.
- 변경 내용, 고려한 부작용, 실제 수행한 검증과 결과, 남은 위험이나 검증하지 못한 영역을 보고합니다. 부작용이 불가능하다거나 테스트하지 않은 동작이 검증되었다고 주장하지 않습니다.
