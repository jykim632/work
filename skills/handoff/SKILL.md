# Handoff

Capture enough verified context for the next session to continue without rediscovering the work.

## Working approach

- Follow applicable project instructions and existing user preferences for destinations, privacy, and external actions.
- Review available conversation context, Git status, branch and worktree, relevant diff, and recorded checks. Do not attribute unrelated changes to the current task.
- Use the requested destination and format. If none is specified, provide the note in the conversation rather than choosing an external service or creating a repository file.

## Prepare the continuation note

- State the objective and accepted scope, what is complete, and what remains. Separate implementation completion from validation and publication status.
- Include decisions and their concrete reasons, relevant constraints, and references to files, issues, or artifacts needed to continue. Avoid copying an entire transcript or diff.
- Record checks actually performed and their results. Distinguish confirmed findings, hypotheses, pending operations, and blockers.
- Identify the current branch and worktree when relevant, including important uncommitted work. Do not claim that a local file or temporary path will be available on another machine.
- Give the next useful actions in dependency order, including any missing information or authorization. Do not imply that the note grants new permissions.
- Exclude credentials, private payloads, and unnecessary personal data. Sending the note to another person or publishing it requires explicit authorization.
