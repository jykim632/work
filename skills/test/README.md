# Test — 테스트

이 문서는 [SKILL.md](SKILL.md)의 한글 번역본입니다. 스킬 실행 지침의 기준은 영문 원문입니다.

**설명:** 테스트를 통과시키기 위해 제품 동작을 바꾸지 않으면서, 회귀 검증과 실패 경로를 포함한 기존 동작의 자동화 테스트를 추가하거나 강화합니다.

관찰 가능한 동작을 검증하는 집중된 테스트를 통해 기존 작업 흐름에 대한 신뢰도를 높입니다.

## 작업 방식

- 도구, Git 작업 방식, 코딩 규칙, 승인에 관한 프로젝트 지침과 기존 사용자 선호를 따릅니다.
- 관련 구현, 공개 호출부, 테스트 픽스처, 주변 테스트를 살펴봅니다. 기존 테스트 프레임워크와 명령을 재사용합니다.
- 요구사항과 계약에서 기대 동작을 정합니다. 구현이나 기존 검증문이 맞다고 전제하지 않습니다.

## 유용한 검증 범위 파악

- 구체적인 위험이나 보고된 결함을 근거로 누락된 검증의 우선순위를 정합니다. 관련된 경우 성공 경로, 의미 있는 경계 조건, 예상되는 실패를 다룹니다.
- 동작을 관찰할 수 있는 가장 좁은 테스트 수준을 선택합니다. 위험이 실제 구성 요소 간 경계에 걸쳐 있다면 그 경계를 mock으로 없애지 말고 통합 테스트를 사용합니다.
- 테스트 결과가 일정하게 유지되도록 하며 운영 데이터, 외부 계정, 실제 시간의 흐름과 분리합니다. 외부 시스템은 기존에 정한 경계에서 mock으로 대체하되, 테스트 안에서 구현을 다시 만들지 않습니다.

## 구현과 검증

- 결과, 오류, 부수 효과에 대한 명확한 검증문을 추가합니다. 동작상 이유 없이 내부 호출 순서만 확인하거나 구현 로직을 반복하는 테스트는 피합니다.
- 회귀 테스트에서는 가능한 경우 해당 테스트가 보고된 결함을 드러내는지 보여줍니다. 의도한 회귀 실패와 잘못된 테스트 환경 설정을 구분합니다.
- 통과 결과를 얻기 위해 검증문을 약화하거나 제품 동작을 변경하지 않습니다. 테스트에서 결함이 드러나면 보고하고, 요청 범위에 구현 변경이 포함된 경우에만 수정합니다.
- 해당 테스트와 관련 포매터 또는 타입 검사를 실행합니다. 공통 픽스처나 보조 함수를 변경했다면 검증 범위를 넓힙니다.
- 추가한 검증 범위, 실행한 명령과 결과, 발견한 결함, 아직 검증하지 못한 동작을 보고합니다.
