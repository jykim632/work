# GitHub CI Fix — CI 오류 수정

이 문서는 [SKILL.md](SKILL.md)의 한글 번역본입니다. 스킬 실행 지침의 기준은 영문 원문입니다.

**설명:** 로그를 특정 커밋과 연결하여 PR에서 실패한 GitHub Actions 검사를 조사하고 수정하며, 범위에 맞는 수정 결과를 검증합니다.

실패한 GitHub Actions 검사를 진단하고 요청 범위 안에서 원인을 수정합니다.

## 작업 방식

- Git 작업 방식, 도구, 코딩 규칙, 승인에 관한 프로젝트 지침과 기존 사용자 선호를 따릅니다.
- 적절한 연결된 GitHub 도구나 인증된 `gh` CLI를 사용합니다. 결론을 내리기 전에 저장소, PR, head 커밋, 실패한 검사를 확인합니다.
- 조사만 요청한 경우에는 수정 권한이 부여되지 않습니다. 수정 요청은 범위에 맞는 로컬 수정을 허용하지만, 커밋 게시나 워크플로 재실행에는 해당 작업의 승인이 필요합니다.

## 실패한 검사 진단

- 검사 상태, 실행 메타데이터, 관련 작업 로그를 읽습니다. 현재 head와 이전 실행을 구분하고, 실패한 실행과 아직 진행 중이거나 취소된 실행을 구분합니다.
- 처음으로 조치할 수 있는 실패를 찾고 그로 인해 뒤따른 오류와 구분합니다. 관련이 있다면 변경된 코드를 워크플로 설정, 런타임 버전, 의존성 설치 과정과 비교합니다.
- 근거를 바탕으로 코드 결함, 테스트 결함, 환경 문제, 권한 오류, 일시적인 서비스 문제를 구분합니다. 설명되지 않은 실패를 단순히 불안정한 테스트라고 분류하지 않습니다.
- 로그를 사용할 수 없거나 검사가 지원되지 않는 외부 제공자의 것이라면, 진단을 만들어내지 말고 한계와 상세 정보 링크를 보고합니다.

## 수정과 검증

- 가능한 경우 실패한 명령을 로컬에서 재현합니다. 원인을 해결하는 가장 작은 수정을 적용하고, 적절한 경우 의미 있는 회귀 검증을 추가합니다.
- 통과 결과를 얻기 위해 검사를 비활성화하거나 검증문을 약화하거나 비밀 정보를 노출하거나 권한을 확대하지 않습니다. 요청한 수리에 실제로 필요한 경우에만 의존성 버전이나 워크플로 설정을 변경합니다.
- 집중된 로컬 검증을 실행합니다. 로컬 통과가 원격 CI 통과를 의미하지는 않습니다. 각각을 구분하여 보고하고 원격 결과를 해당 커밋과 연결합니다.
- 승인받았고 워크플로의 부수 효과를 이해한 경우에만 CI를 재실행합니다. 새로운 근거나 종료 기준 없이 재시도를 반복하지 않습니다.
- 실패한 검사와 실행 링크, 원인과 근거, 수정 내용, 검증 결과, 남은 원격 검사를 보고합니다.
