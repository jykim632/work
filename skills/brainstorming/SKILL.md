# Brainstorming

Help the user discover and refine possible approaches to a goal. Generate useful alternatives, challenge assumptions constructively, and make the important choices explicit.

## Understand the goal

- Follow applicable project instructions and existing user preferences for language, tooling, conventions, and approvals.
- Identify the desired outcome, intended users, known constraints, and decisions already made from the request and prior conversation.
- For an existing project, inspect relevant context when it materially informs the options. A standalone idea does not require a repository.
- Ask focused questions when missing information would materially change the options. Avoid a long questionnaire; otherwise proceed with clearly stated assumptions.
- Briefly state the goal and the part of the problem being explored.

## Explore alternatives

- Treat the user's initial idea as a candidate to examine. Identify its strengths, limitations, and underlying assumptions without automatically endorsing or rejecting it.
- Offer a small set of materially different approaches when alternatives would help. Do not force a fixed number of options or invent weak alternatives to fill a list.
- Explain how each approach works and why it might suit the goal. Include the current approach or a simpler alternative when either is a meaningful choice.
- Separate established facts from assumptions, preferences, and ideas that still need validation.
- Check relevant sources when feasibility depends on uncertain or changing technical capabilities. Keep research focused on decisions that matter.

## Compare and refine

- Compare options against the user's goals and relevant constraints, such as user experience, implementation effort, compatibility, operational complexity, and reversibility.
- Make consequential tradeoffs concrete. Avoid presenting one option as universally best.
- Recommend a direction when the evidence supports one, explaining why and what could change the recommendation.
- Ask for the user's preference when a meaningful tradeoff cannot be resolved from existing context. Continue independent exploration while awaiting that decision.
- Incorporate feedback and narrow the options. Do not reopen settled choices without new evidence or a changed requirement.
- If uncertainty blocks a useful choice, propose the smallest experiment or prototype that could resolve it and explain what its result would establish.

## Capture the outcome

- Summarize the proposed or selected direction, rationale, important tradeoffs, unresolved questions, and next useful step.
- Distinguish a recommendation from a decision the user has actually made.
- If the user wants open-ended ideation, preserve promising options without forcing a final choice.
- When enough decisions are settled for the user's purpose, stop expanding the idea and provide a concise handoff.

Brainstorming alone does not authorize project changes, prototype implementation, publication, or external actions. If the user explicitly requests implementation, continue from the agreed decisions without requiring them to repeat the context or invoke another command.
