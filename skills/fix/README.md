# Fix — 결함 수정

이 문서는 [SKILL.md](SKILL.md)의 한글 번역본입니다. 스킬 실행 지침의 기준은 영문 원문입니다.

**설명:** 기대 동작을 정하고 원인을 파악하여 코드, 문서, 설정의 결함을 수정하며, 수정 결과와 영향을 받는 작업 흐름을 검증합니다.

의도한 수정 범위 밖의 동작을 유지하면서 보고된 결함을 수정합니다. 이 명령과 함께 증상을 전달하면 조사, 수정, 검증을 요청한 것으로 봅니다. 사용자가 확인만 명시적으로 요청했다면 파일을 수정하지 않고 조사와 보고만 수행합니다.

## 작업 방식

- 사용자가 다른 언어를 요청하지 않는 한 사용자의 언어로 답합니다.
- 도구, Git 작업 방식, 코딩 규칙, 승인에 관한 프로젝트 지침과 기존 사용자 선호를 따릅니다.
- 짧은 요청에서 시작합니다. 질문하기 전에 관련 구현, 문서, 호출부, 테스트를 살펴봅니다.
- 사용자 설명, 요구사항, 기존 동작 계약, 신뢰할 수 있는 공식 자료에서 기대 동작을 정합니다. 현재 구현이나 테스트가 맞다고 전제하지 않습니다.
- 해결되지 않은 모호함이 수정 방향에 실질적인 영향을 줄 때만 질문합니다. 결함 수정과 새로운 요구사항 도입을 구분합니다.

## 변경 전 진단

- 가능한 경우 문제를 재현합니다. 그렇지 않다면 결함을 설명할 충분한 근거를 수집하고 재현하지 못한 부분을 밝힙니다. 승인 없이 실제 데이터나 외부 상태를 바꾸는 확인은 피합니다.
- 원인과 영향을 받는 작업 흐름을 추적합니다. 확인된 사실과 가설을 구분합니다.
- 문서 결함에서는 설명, 예제, 지침을 의도한 동작 및 신뢰할 수 있는 공식 자료와 대조합니다. 코드와 문서가 다르면 수정 방향을 선택하기 전에 어느 쪽이 의도한 계약을 반영하는지 판단합니다.
- 같은 결함이 있거나 수정의 영향을 받을 수 있는 유사한 사례와 공통 사용처를 확인합니다. 조사 범위를 근거에 비례하도록 유지합니다.

## 수정과 검증

- 원인을 해결하는 가장 작고 일관된 수정을 적용합니다. 관련 없는 정리나 증상만 숨기는 변경은 피합니다.
- 의도한 수정 범위 밖의 동작을 유지합니다. 올바른 수정에 호환성을 깨뜨리는 변경, 데이터 수정, 더 넓은 작업이 필요하다면 영향을 설명하고, 적용되는 승인 요건 안에서 중요한 선택을 사용자와 해결합니다.
- 가능한 경우 수정 전 결함을 보여주고 수정 후 결과를 검증합니다. 재발 방지에 실질적인 도움이 된다면 회귀 테스트나 지속적으로 활용할 수 있는 검증 수단을 추가합니다.
- 관련 실패 경로와 변경의 영향을 받는 기존 작업 흐름을 확인합니다. 문서에서는 해당하는 경우 수정된 설명, 링크, 실행 가능한 예제를 검증합니다.
- 원인, 수정 내용, 고려한 부작용, 실제 수행한 확인과 결과, 남은 불확실성을 보고합니다. 뒷받침하는 근거 없이 근본 원인이 확정되었다거나 검증에 성공했다고 주장하지 않습니다.
