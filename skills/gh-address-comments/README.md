# GitHub Review Comments — PR 리뷰 대응

이 문서는 [SKILL.md](SKILL.md)의 한글 번역본입니다. 스킬 실행 지침의 기준은 영문 원문입니다.

**설명:** GitHub PR의 리뷰 의견을 평가하고 대응합니다. 요청한 각 스레드에 대해 범위에 맞는 수정, 검증, 근거가 있는 처리 결과를 제공합니다.

요청받은 PR 리뷰 피드백을 타당한 수정과 명확한 처리 기록으로 연결합니다.

## 작업 방식

- Git 작업 방식, 도구, 코딩 규칙, 승인에 관한 프로젝트 지침과 기존 사용자 선호를 따릅니다.
- 적절한 연결된 GitHub 도구나 인증된 `gh` CLI를 사용합니다. 저장소, PR, 현재 head, 요청한 리뷰 스레드를 확인합니다.
- 관련 의견 전체, 주변 diff, 현재 구현, 호출부, 테스트를 읽습니다. 스레드에 아직 조치가 필요한지 판단하기 전에 페이지네이션, 답글, 오래된 줄 참조를 고려합니다.

## 평가와 구현

- 조치 가능한 결함이나 요구사항을 질문, 선호, 중복 의견, 이후 변경으로 이미 충족된 피드백과 구분합니다.
- 리뷰어의 주장을 코드 및 의도한 동작과 대조합니다. 회귀를 만들거나 합의한 계약과 충돌하는 피드백을 무조건 구현하지 않습니다.
- 사용자가 조치 가능한 피드백 전체를 요청했다면 스레드마다 선택하도록 요구하지 않고 근거가 있는 수정을 진행합니다. 상충하는 피드백이나 미해결 제품 결정이 결과에 실질적인 영향을 줄 때만 질문합니다.
- 요청받은 의견에 대해 가장 작고 일관된 수정을 적용하고 관련 없는 변경을 보존합니다. 집중된 검증을 실행하고, 공통 동작이 바뀌었다면 영향을 받는 사용처를 확인합니다.

## 처리 결과 보고

- 요청받은 각 스레드에 대해 대응 완료, 이미 충족됨, 근거상 적용 대상 아님, 사유가 있는 미해결 상태 중 어디에 해당하는지 밝힙니다. 관련 파일이나 테스트를 참조합니다.
- 도움이 된다면 간결한 답글 초안을 작성합니다. 근거 없이 성공을 주장하지 말고 수정 내용과 검증을 설명합니다.
- 답글 게시, 원격 스레드 해결 처리, 커밋, push에는 각각에 대한 명시적 승인이 필요합니다. 로컬 코드 수정 요청만으로 해당 권한이 부여되는 것은 아닙니다.
- 승인받은 스레드 해결 처리 전에 현재 코드가 지적 사항을 해결했는지 확인합니다. 리뷰 목록을 비우기 위해 의견 불일치나 검증되지 않은 수정을 해결 완료로 처리하지 않습니다.
- 로컬 변경과 검증은 실제 완료한 원격 답글이나 스레드 해결 처리와 구분하여 보고합니다.
