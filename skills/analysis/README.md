# Analysis — 분석

이 문서는 [SKILL.md](SKILL.md)의 한글 번역본입니다. 스킬 실행 지침의 기준은 영문 원문입니다.

**설명:** 프로젝트를 수정하지 않고 코드, 문서, 관련 자료의 근거를 바탕으로 기존 동작과 구조를 설명하고, 제시된 설계를 평가하며, 제안된 변경의 영향을 분석합니다.

어떤 대상이 어떻게 동작하는지, 어떤 구조인지, 특정 접근 방식이 요구사항에 적합한지, 제안된 변경이 어디에 영향을 미치는지에 관한 사용자 질문에 답합니다. 분석이 반드시 결함을 찾거나 변경을 권고해야 한다고 전제하지 않습니다.

## 질문과 범위 확정

- 언어, 도구, Git 작업 방식, 코딩 규칙, 승인에 관한 프로젝트 지침과 기존 사용자 선호를 따릅니다.
- 요청과 앞선 대화에서 분석 대상과 답해야 할 질문을 파악합니다.
- 사용자가 원하는 것이 동작 설명, 구조 분석, 평가, 제시된 선택지 비교, 변경 영향 분석 또는 이들의 조합인지 판단합니다.
- 대상이나 목적이 불명확하여 분석 방향이 크게 달라질 수 있다면 조사 전에 질문합니다. 의도가 이미 명확한 경우에는 사용자에게 분석 유형을 선택하도록 요구하지 않습니다.
- 질문과 시작 범위를 짧게 알립니다. 직접 관련된 의존성과 사용처를 추적하며, 이미 허용된 경우를 제외하고 별도 기능이나 시스템으로의 범위 확대를 확인합니다.

## 근거 수집과 해석

- 관련 구현, 문서, 설정, 호출부, 기존 테스트를 살펴봅니다. 어느 하나를 절대적인 기준으로 전제하지 않고 각각을 근거로 취급합니다.
- 동작과 구조를 분석할 때는 질문에 관련된 진입점, 책임, 데이터 흐름, 상태 전환, 의존성을 추적합니다.
- 평가나 비교에서는 적합성을 판단하기 전에 요구사항과 평가 기준을 정합니다. 개인적 선호가 아닌 해당 기준에 따라 장단점과 절충 사항을 설명합니다.
- 변경 영향 분석에서는 영향을 받는 계약, 사용처, 저장 데이터, 작업 흐름을 추적합니다. 직접적인 영향과 특정 조건에서 발생하거나 추정에 머무는 영향을 구분합니다.
- 구체적인 불확실성을 해소할 수 있을 때만 기존 검증 수단이나 브라우저 관찰을 사용합니다. 실행 전에 목적을 설명합니다.
- 사실, 추론, 가정, 해결되지 않은 질문을 구분합니다. 근거의 충돌이 결론에 영향을 준다면 조사합니다.

## 작업 경계와 종료 기준

- 프로젝트 소스, 설정, 의존성, 테스트, 비교 기준 스냅샷을 수정하지 않습니다. 분석을 위해 도구를 설치하거나 자동 수정을 실행하지 않습니다.
- 실제 데이터와 외부 상태를 변경하지 않는 확인 방법을 사용합니다. 유용한 증거 산출물은 정해진 임시 산출물 위치나 임시 디렉터리에 보관하며, 비밀 정보나 개인 데이터는 수집하지 않습니다.
- 권고의 범위를 요청에 맞춥니다. 설명 요청이 자동으로 재설계를 요구하는 것은 아니며, 평가 결과 현재 접근 방식이 적절하다고 결론 내릴 수도 있습니다.
- 확정한 범위의 질문에 충분한 근거로 답할 수 있으면 종료합니다. 근거가 부족하여 결론을 내릴 수 없다면 한계와 다음에 수행할 유용한 확인을 밝힙니다.

## 답변 보고

- 사용자 질문에 대한 답을 먼저 제시하고, 뒷받침하는 근거와 판단 과정을 설명합니다.
- 목적에 맞는 형식으로 결과를 제시합니다. 예를 들어 흐름 설명, 책임과 의존성 관계도, 기준에 따른 평가, 비교, 영향 요약을 사용할 수 있습니다.
- 관련 코드나 자료를 참조하고, 직접 관찰한 동작과 코드 등의 조사만으로 도출한 결론을 구분합니다.
- 중요한 가정과 불확실성을 밝힙니다. 사용자가 요청했거나 질문을 해결하는 데 필요할 때 권고나 다음 단계를 포함합니다.

이후 사용자가 구현을 명시적으로 요청하면 기존 조사 결과를 활용하여 진행합니다. 사용자에게 맥락을 반복하거나 다른 명령을 호출하도록 요구하지 않습니다.
