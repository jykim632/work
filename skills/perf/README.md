# Perf — 성능

이 문서는 [SKILL.md](SKILL.md)의 한글 번역본입니다. 스킬 실행 지침의 기준은 영문 원문입니다.

**설명:** 재현 가능한 측정과 동작을 유지하는 변경을 통해 API, 데이터베이스 쿼리, 백그라운드 작업 등 코드의 실행 성능을 조사하고 개선합니다.

측정으로 확인한 병목을 찾고, 비교 가능한 기준값에 비추어 변경을 평가합니다.

## 작업 방식

- 도구, Git 작업 방식, 코딩 규칙, 승인에 관한 프로젝트 지침과 기존 사용자 선호를 따릅니다.
- 느린 작업 흐름, 대표적인 작업 부하, 실행 환경, 중요한 지표를 정합니다. 지표에는 지연 시간, 처리량, 메모리, 자원 사용량 등이 포함될 수 있습니다.
- 브라우저 로딩과 Core Web Vitals는 가능한 경우 전용 웹 성능 워크플로를 우선 사용합니다. 이 워크플로는 요청한 실행 동작에 집중합니다.

## 측정과 진단

- 안전하게 증상을 재현하고 최적화 전에 기준값을 기록합니다. 워밍업, 캐시 상태, 입력 크기, 동시 실행 수, 외부 의존성이 결과에 영향을 준다면 각각의 영향을 구분합니다.
- 기존 프로파일링, 트레이싱, 쿼리 실행 계획, 벤치마크를 사용하여 병목을 찾습니다. 관찰과 가설을 구분하고 코드의 겉모습만으로 병목을 추론하지 않습니다.
- 승인 없이 운영 환경에 부하를 가하거나 상당한 외부 자원을 소비하지 않습니다. 대표적인 조건으로 측정할 수 없다면 한계를 밝히고, 성능 향상이 확인되었다고 주장하지 않습니다.

## 개선과 비교

- 분석만 요청한 경우에는 조사 결과와 권고를 보고하고 마칩니다. 개선을 요청한 경우에는 측정으로 뒷받침되는 가장 작은 변경을 구현합니다.
- 출력, 순서, 오류 처리, 권한 검사, 일관성을 유지합니다. 계약을 바꾸기 전에 메모리, 지연 시간, 데이터 최신성, 복잡성에 관한 중요한 절충 사항을 설명합니다.
- 동일한 조건에서 변경 전후를 비교하고, 측정 잡음이 중요하다면 반복 측정합니다. 근거 없는 백분율만 제시하지 말고 절대값, 작업 부하, 변동성을 보고합니다.
- 관련 동작 검증 테스트를 실행하고 공통 사용처의 회귀를 확인합니다. 재사용 가능한 벤치마크는 프로젝트의 기존 도구 안에서 지속적인 가치가 있을 때만 유지합니다.
- 병목의 근거, 변경 내용, 측정 결과, 절충 사항, 남은 한계를 보고합니다.
