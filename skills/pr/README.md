# PR — Pull Request

이 문서는 [SKILL.md](SKILL.md)의 한글 번역본입니다. 스킬 실행 지침의 기준은 영문 원문입니다.

**설명:** 실제 diff와 확인된 맥락을 바탕으로 Pull Request 제목과 설명을 준비합니다. 원격 PR은 요청한 경우에만 생성하거나 갱신합니다.

범위가 정해진 변경을 실제 diff에 근거한 검토 가능한 PR 설명으로 정리합니다.

## 작업 방식

- Git 작업 방식, 도구, 코딩 규칙, 승인에 관한 프로젝트 지침과 기존 사용자 선호를 따릅니다.
- Git 상태, 대상 base 브랜치, 커밋, 관련 diff 전체를 확인합니다. 아직 커밋하지 않은 변경을 파악하고 원격 PR에 포함될 내용과 구분합니다.
- 저장소의 PR 템플릿과 연결된 이슈가 있다면 읽습니다. 근거에서 의도를 파악하고, 해결되지 않은 선택이 PR 범위나 대상에 실질적인 차이를 만들 때만 질문합니다.

## 검토 내용 준비

- 구체적인 문제와 변경 후 동작을 먼저 설명합니다. 검토자의 이해에 도움이 된다면 짧은 변경 전후 예시를 포함합니다.
- 최종 구현, 관련 호환성 또는 운영 영향, 중요한 한계를 설명합니다. 필요한 절충 사항을 설명하는 경우가 아니라면 폐기한 접근 방식과 대화 이력은 제외합니다.
- 실제 실행한 확인과 결과만 기록합니다. 실행하지 않은 검증을 명시하고, 계획한 테스트를 이미 검증한 것처럼 표현하지 않습니다.
- 변경 규모에 맞게 제목과 본문을 작성하고 저장소 템플릿을 따릅니다. 실제로 이슈를 해결하며 종료가 의도된 경우에만 이슈를 닫는 키워드를 사용합니다.

## 요청받은 경우 게시

- 설명 작성만으로 커밋, push, 원격 PR 생성이 허용되는 것은 아닙니다. 해당 작업에 대한 기존의 명시적 승인이 있다면 다시 요청하지 않고 활용합니다.
- 요청받은 원격 작업 전에 저장소, head 브랜치, base 브랜치, 기존 PR을 확인하여 중복 생성이나 관련 없는 변경의 게시를 방지합니다.
- 본문은 구조화된 인자로 전달하는 방식을 우선합니다. `gh`를 사용할 때는 여러 줄의 텍스트를 임시 파일에 작성하고 `--body-file`로 전달하여 형식을 보존하고 셸 치환을 피합니다.
- 준비한 제목과 본문을 보고하거나, 요청받은 게시가 성공했다면 생성 또는 갱신한 PR 링크를 제공합니다. PR에 포함되지 않은 로컬 작업도 밝힙니다.
