# Playwright — 브라우저 검증

이 문서는 [SKILL.md](SKILL.md)의 한글 번역본입니다. 스킬 실행 지침의 기준은 영문 원문입니다.

**설명:** Playwright를 사용하여 브라우저 작업 흐름을 조사하고 실행하며, UI 문제를 재현하고 근거를 수집합니다. 자동화된 브라우저 테스트는 요청받았거나 구현 범위상 필요한 경우에만 추가합니다.

관찰 가능한 단계와 결과의 근거를 통해 실제 브라우저 작업 흐름을 검증합니다.

## 작업 방식

- 도구, Git 작업 방식, 코딩 규칙, 승인에 관한 프로젝트 지침과 기존 사용자 선호를 따릅니다.
- 기존 브라우저 자동화, 테스트 설정, 실행 명령, 대상 환경을 살펴봅니다. 프로젝트에 설치된 Playwright 도구나 해당 작업을 지원하는 사용 가능한 브라우저 커넥터를 우선합니다.
- 도구를 사용하기 전에 해당 도구의 문서를 확인합니다. 특정 CLI, 래퍼 스크립트, 브라우저, 인증된 세션이 있다고 가정하지 않습니다. 의존성을 추가하기 전에 빠진 사전 조건을 설명합니다.

## 작업 흐름 실행

- 대상 URL, 기대 동작, 관련 화면 크기 또는 브라우저를 정합니다. 로컬 환경이나 명시적으로 허용된 테스트 환경을 우선합니다.
- 조작 전에 현재 페이지를 확인합니다. 접근성 역할, 레이블, 기존 테스트 식별자를 사용합니다. 페이지 이동이나 중요한 UI 변경 후에는 오래된 요소 참조를 재사용하지 않고 스냅샷을 갱신합니다.
- 임의의 지연 시간을 두는 대신 관찰 가능한 애플리케이션 상태를 기다립니다. 요청에 맞는 범위에서 성공, 빈 상태, 로딩, 실패 동작을 확인합니다.
- 브라우저 세션을 사용할 수 있다는 이유만으로 구매를 제출하거나, 메시지를 보내거나, 실제 레코드를 삭제하거나, 외부 데이터를 변경하지 않습니다. 부수 효과가 있는 작업에는 격리된 픽스처와 기존에 부여된 권한을 활용합니다.
- 결과 설명에 도움이 된다면 스크린샷, 콘솔 오류, 네트워크 근거, 트레이스를 수집합니다. 산출물에 자격 증명이나 비공개 페이지 데이터를 저장하지 않습니다.

## 결과 보고와 유용한 근거 보관

- UI 결함과 실행 환경, 인증, 네트워크, 자동화 실패를 구분합니다. 직접 확인하지 않은 근본 원인을 주장하지 말고 실패한 단계와 뒷받침하는 근거를 보고합니다.
- 요청받은 테스트 파일은 기존 테스트 프레임워크를 따릅니다. 픽스처를 격리하고 사용자에게 보이는 결과를 중심으로 검증문을 작성합니다.
- 유용한 산출물은 프로젝트에서 정한 출력 위치에 저장하고 경로를 명시합니다. 환경, 실행한 단계, 관찰한 결과, 검증하지 못한 경로를 보고합니다.
